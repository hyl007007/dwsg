## 实际联网验证

- 本机游戏 Host 只监听 `127.0.0.1:57119`；经已有 Cloudflare 命名隧道，`game.dwsg-game.com/health` 与 `auth.dwsg-game.com/api.php?appid=1` 的公网 HTTPS 检查均返回 200。验证过实际 UnityWebRequest 的公网登录、连接、轮询和断开。另用隔离测试账号经公网发送一个必定拒绝的未知命令，确认 `/command` 返回 `InvalidArgument`，之后继续轮询成功；此命令不会修改游戏世界。
- 为避免本机已有系统代理绕行，只把上述两个域名加入 Windows 当前用户的代理例外列表，保留原列表并在被忽略目录备份。此项是本机环境设置，不是可移植的客户端配置。命名隧道的独立 QUIC 连接期间曾出现少量超时和自动重连警告，但持续测试没有记录到请求失败；结束后入口再次确认可达。
- 本地启动和健康监控、测试账号、测量脚本、日志均位于被 `.gitignore` 排除的 `audit/`，不加入仓库。监控共记录 104 次 `ready`、0 次 `failed`。压测结束后发现监控脚本把 UTC 截止时间按本地时间比较，已停止该监控进程，并在本地忽略脚本中改用 `DateTimeOffset`；游戏、认证、数据库和隧道服务没有因此停止。
- SQLite 世界库在持续测试结束后的 `PRAGMA quick_check` 为 `ok`。截至本报告编写时，两个公网入口仍返回 200。

### 持续测试结果

公网和本地是同一台 Windows 机器上的两条访问路径，各使用一个隔离测试账号。公网持续测试从北京时间 11:52 至 13:31，约 99 分钟；本地对照从 12:14 至 13:31，约 77 分钟。测试进程按时断开并退出。

| 路径 | 成功轮询 | 失败 / 重连 | 各分钟 p50 的中位数 | 各分钟 p95 的中位数 | 最慢单次 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Cloudflare 公网 HTTPS | 2,646 | 0 / 0 | 1,720 ms | 3,173 ms | 8,571 ms |
| 本机回环 HTTP | 2,282 | 0 / 0 | 848 ms | 1,822 ms | 3,275 ms |

这里的“各分钟 p50 的中位数”是先逐分钟统计，再取这些分钟结果的中位数；日志没有保存每次轮询的原始时长，因此不能把它表述成所有请求合并后的精确 p50。公网健康接口单独测得约 0.54～0.62 秒 p50，本地健康接口近乎即时。公网轮询多出的等待既有公网链路开销，也受游戏 Host 本身处理耗时和负载影响；这组同机测试不能代表异地手机网络。

一次连接对照中，初始快照未压缩约 650 KB，Cloudflare 向客户端提供 gzip 后约 52 KB，但该次公网连接仍约 6 秒。曾尝试给 Host 增加源站响应压缩并编译成功；自动审批以 `blocked by policy` 拒绝离屏启动第二个、使用数据库副本的隔离验收进程。压缩改动随即撤回，**没有部署，也没有计入上述三条提交**。不能根据单次对照声称压缩已经降低连接延迟。

## 尚未解决及交付边界

1. **公网可用，但延迟和尾部波动仍明显。** 最慢轮询 8.57 秒，不能称作低延迟稳定版。测试期间隧道请求错误计数为 0；个别 QUIC 连接超时后自动恢复，不等于这条网络今后不会中断。
2. **本机 Host 性能仍是限制。** 两名持续测试用户期间曾测得约 4.2～4.5 个 CPU 核心的使用量，本地轮询也变慢。压测结束时进程私有内存约 1,458 MiB；报告编写时又观察到约 1,916 MiB。尚未做内存剖析，不能断言内存泄漏，但在部署到内存较小的 RK3568 前必须调查。服务端处理优化由其他成员负责，本窗口未把它算作自己的修复。
3. **验收范围有限。** 已验证本机经真实公网域名和隔离 Unity 网络请求的功能路径；没有异地独立设备、真实移动网络、五台同时联网设备、正式 Windows 玩家包、Android 或 RK3568 的本轮验收。当前公网入口依赖本机、PHP、MariaDB、游戏 Host 和 Cloudflare 隧道持续运行，`audit/` 下的临时监控脚本不是正式部署包。
