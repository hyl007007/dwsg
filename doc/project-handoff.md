## 当前结论

项目已经有 Unity 客户端、PHP 账号授权、独立 C# 游戏服务器和 SQLite 世界持久化。原界面经适配发送服务端命令，再读取授权后的公共/私人状态。本机已验证五个实际编译客户端同时登录、创建独立角色、操作及同步；不能再按“只有单机，没有游戏服务器”的旧描述开发。

当前属于**本机联机开发验证阶段**。目标仍是安卓客户端、RK3568 上的服务器、同一局域网最多五人。用户暂定 RK3568 为 Debian 10、4 GB 内存、64 GB 存储；两类设备尚未接入，APK、板端部署、五台手机联机和长时间稳定性尚未验收。

已有页面、原图标和业务规则优先复用。不要把现有城池信息、国家、出征、战斗等界面重新做一套；先查场景、预制件、按钮绑定及脚本。关闭按钮沿用工程图标，新增内容使用现有组件和布局方式。

## 本机环境与构建限制

- 源工程 `web/ProjectSettings/ProjectVersion.txt` 仍为 **2022.1.23f1c1（46637c7592ee）**。
- 本机安装 **Unity 6000.3.20f1**；验证在 `audit/deployment/unity-project/` 副本中适配并构建，主工程没有整体迁移到 Unity 6。未在原 Unity 2022 中国版重新编译。
- 本机服务器使用 **.NET SDK 10.0.401 / net10.0**；PHP 8.4、MariaDB 11.4.8 和 SQLite 使用隔离目录及测试账号。
- Windows 构建成功不等于 Android 构建成功。Android Build Support、SDK/NDK/JDK、旧原生插件、ARM64/IL2CPP、签名和安装仍须处理。
- Debian 10 与目标 .NET/原生依赖的兼容性必须在板上确认；不假设自包含发布自动解决系统兼容性，也不擅自刷系统。
- 本机测试服务只绑定回环地址，按实例归属清理进程。不要为了阅读文档重启 Wine、绘图示例或旧客户端。

## 服务连接与数据边界

构建入口为 `dotnet build server/Host/Dwsg.Host.csproj`，需要 .NET 10 SDK。运行配置来自环境变量，真实值只放本地部署配置，不写进源码。

| 配置 | 用途 |
| --- | --- |
| `DWSG_WORLD_DB` | 游戏世界 SQLite 文件路径，必填 |
| `DWSG_WORLD_ID` | 世界 ID，默认 `main` |
| `DWSG_WORLD_SEED` | 首次建库需要的原工程世界导出；已有有效世界不重复导入 |
| `DWSG_AUTH_URL` | PHP `api.php?appid=…` 授权地址；Host 必填，客户端登录也读取此配置 |
| `DWSG_MAX_ONLINE_PLAYERS` | 默认 5，NPC 不计入真人连接名额 |
| `DWSG_SESSION_LEASE_MS` | 会话租期，现有默认 30000 ms |
| `ASPNETCORE_URLS` / `--urls` | Host 监听地址；本机隔离使用 `127.0.0.1` |
| `DWSG_GAME_URL` | 客户端游戏服务地址；现有客户端还可读同名 PlayerPrefs |
| `DWSG_NATION_IMPORT_PROOF`、`DWSG_NATION_IMPORT_PROOF_SHA256` | 旧世界缺少国家稳定映射版本时需要合格导入证明及摘要 |

Host 提供 `/health`、`/connect`、`/command`、`/poll`、`/disconnect`。命令沿用认证、世界、玩家和请求 ID 校验；不接受客户端自行提交余额、伤亡或最终胜负。

手机上的 `127.0.0.1` 指手机自己。实机部署须配置板端地址、认证服务、证书及网络规则；回环 HTTP 测试不是正式局域网配置。全新克隆没有忽略的数据库、世界种子或凭据，不能直接当一键安装包。

游戏世界在 SQLite，PHP 账号在 MariaDB。Host 已有备份入口：正确配置世界数据库与世界 ID 后使用 `--backup <目标路径>`。备份恢复、迁移及升级回滚仍须在目标环境演练。
