## 1. 接手时先知道的事

1. **这是 Unity C# 客户端 + PHP 授权管理后台，当前主要是本地游戏模拟。** 文件夹叫 `web/`，不代表客户端是网页游戏；此前浏览器展示的是远程画面。
2. 已在隔离环境中构建并试玩 Windows 客户端，修复了一批启动、存档、商城、会话、文字和窗口卡顿问题；这不等于安卓和五人联机已经完成。
3. 用户目标是安卓客户端、RK3568 服务器、最多 5 人同一局域网联机。板端暂定 Debian 10、4GB 内存、64GB 存储；系统/运行时兼容性需要先验证，具体路线见模块方案。
4. **试玩客户端、浏览器画面、PHP、MariaDB、临时测试浏览器和 `DWSG-Preview` WSL 环境已经关闭。** 不要为了读文档或检查仓库自动重启它们。
5. 所有必要验证完成后做本地 Git 提交；只有用户明确要求才上传 GitHub。本次用户明确要求两份文档本地提交并推送远端。

### 关键代码事实

- [`全局变量.cs`](../web/Assets/Scripts/全局变量.cs) 持有玩家、国家、城池、军情、战场以及 Unity 对象的静态列表；`本机身份` 默认是列表下标 0。

- [`玩家数据.cs`](../web/Assets/Scripts/玩家数据结构/玩家数据.cs) 同时包含数据、计算和全局访问；初始化资源仍有 `99999` 等试玩数值，未作正式经济平衡评估。
- [`战斗系统.cs`](../web/Assets/Scripts/战斗系统.cs) 在 Unity 更新周期内结合对象渲染、兵力和城池数据结算，不能直接充当 RK3568 无界面服务器模块。
- [`TIME.cs`](../web/Assets/Scripts/TIME.cs) 使用本机 `DateTime.Now`；[`网络时间类.cs`](../web/Assets/Scripts/网络时间类.cs) 只是一个数据类型，不是已实现的权威时间同步服务。
- [`登录脚本.cs`](../web/Assets/Scripts/改版脚本/登录脚本.cs) 默认请求 `http://127.0.0.1:18080/api.php?appid=1`，可通过 `DWSG_AUTH_URL` 环境变量覆盖；安卓手机的 `127.0.0.1` 指向手机自身，必须增加适合安卓的服务器地址配置。

### 会话和数据修复的实际边界

PHP 登录发放随机会话凭据，服务端只存其哈希；相关入口验证应用、账号、客户端、心跳 ID 与凭据归属。已修复的 `setudata` 使用参数化写入，并检查 UTF-8/长度；这不表示每个旧 API 都已经采用同样的安全策略。新增游戏命令必须独立做身份、对象归属与参数验证。

存档现在验证槽位、版本和必要结构，先写临时文件并校验，再替换正式文件；读取失败可回退 `.bak`。这种文件保存方案已经改进单机可靠性，但不能替代服务器事务、并发控制和命令去重。

### 卡顿修复的原因与效果

发现的两个主要原因是：多个旧试玩实例同时在隔离环境中进行软件渲染；打开新功能窗口时旧窗口仍激活，越开越多，关闭一个后其他窗口继续渲染。

新增代码：[`界面窗口管理器.cs`](../web/Assets/Scripts/界面窗口管理器.cs)、[`界面互斥窗口.cs`](../web/Assets/Scripts/界面互斥窗口.cs)、[`界面点击来源.cs`](../web/Assets/Scripts/界面点击来源.cs)。当前规则：

- 主导航切换只保留一个功能窗口，并清理旧返回路径。
- 从窗口进入子窗口时隐藏父窗口，关闭子窗口按层级返回。
- 地图/封地/战斗切换处理窗口清理；不会每帧全场景扫描来寻找窗口。
- 管理范围主要是主场景根级 `ScreenSpaceOverlay` Canvas 的排序层 2–9，排除战斗结算界面；地图、战场、提示和同一 Canvas 内的深层面板另行处理。未来新增 UI 需验证是否被纳入管理。

同一离屏测试场景中，旧版连续打开出现 7 个可见窗口，关闭顶层仍剩 6 个；修复后每次保留 1 个，最终关闭为 0。短样本帧耗时均值从约 `129.5ms` 降至 `56.0ms`，p95 从约 `184.5ms` 降至 `82.6ms`。这证明叠窗问题得到改善，**不是“所有卡顿已消失”的结论**。

隔离画面走 Wine / Xvfb / llvmpipe 软件渲染 / noVNC，未使用本机 RTX 4060 Ti 硬件加速。真实点击到画面变化仍测到约 200–360ms 的链路延迟；不能据此推断安卓原生速度，也不能把本机剩余高 CPU 全部归因于网络或游戏逻辑。关闭旧实例是资源管理要求，后台示例绘图不是运行游戏的必要条件。

### 读取状态与按需恢复

接手时使用以下只读命令，不启动 WSL：

```powershell
& 'D:\Git\cmd\git.exe' status --short
& 'D:\Git\cmd\git.exe' log -8 --oneline
wsl.exe --list --quiet --running
```

**注意：`deploy/preview.ps1 status` 也会调用 `wsl --exec`，因此会启动已停止的发行版。** 没有新的试玩/验证需求时不要调用它。

如果后续任务确实需要恢复本机试玩，已有初始化环境可使用：

```powershell
.\deploy\preview.ps1 start       # 启动 PHP 和数据库
.\deploy\preview.ps1 play        # 复用已有玩家或启动默认玩家
```

以上脚本不会从 GitHub 克隆自动安装 WSL、构建玩家或配置数据库；`audit/` 中的环境准备工具也没有上传。安卓/RK 部署应另外交付可复现脚本，不能依赖这些本机私有产物。

已知控制脚本限制：`stop-play` 主要停止默认 `wine` / `:119` 链路，不能保证停止替换版本的 `wine-visual4` / `:120`。`stop` 只停 PHP/数据库，不停全部游戏。上次完整关闭先结束对应 Wine/画面/测试实例、停止后台，再执行 `wsl.exe --terminate DWSG-Preview`；发行版、项目端口与项目进程均核验为已停止。M10 后续应统一实例登记和全量停止，防止再次积累后台。

不要使用 `wsl --shutdown` 或按程序名批量结束无关软件来代替项目级清理。此前用户允许打开试玩画面，不表示允许改变电脑其他任务。

## 8. 新窗口的操作约束与交付方式

以仓库 [`AGENTS.md`](../AGENTS.md) 和用户最新指令为准。当前已确认的偏好：

- 每次更新经过必要验证后本地 Git 提交；没有明确“上传/推送”指令时不推送远端。保留远端历史，不强制覆盖。
- 不生成每一步的 Markdown 记录；用户明确要求的文档放 `doc/`，最终交付需要的说明可按需维护。
- 测试账号、数据库、日志、截图、临时探针、构建缓存和凭据不提交。`.gitignore` 已排除 `audit/`、真实后台配置、Unity缓存和签名密钥等；新目录产生的运行数据仍需补充忽略规则。
- 后台命令、自动测试和源码分析保持离屏/隔离。用户曾允许观看游戏画面；新开桌面软件仍应按当前任务范围判断，不运行来源不明的原始可执行文件。
- 不需要的测试/示例和旧实例必须关闭。当前关闭状态继续保持，直到任务需要运行。
- 多窗口使用模块所有权和独立工作目录，不在同一目录抢分支、同时写全局脚本或合并 Unity 场景。

本机 Git 可使用 `D:\Git\cmd\git.exe`。远端 `origin` 的读取地址为 HTTPS、推送地址为 SSH，当前本机 SSH 授权曾成功推送；密钥路径和权限不要求其他窗口复制，也不将私钥/公钥内容写入文档。

接手窗口的第一次交付应包含：负责模块、基线提交、实际改动、验证结果、已知限制及本地提交哈希。集成窗口依据[模块方案](module-plan.md)统一接口、接线和最终发布验收。
