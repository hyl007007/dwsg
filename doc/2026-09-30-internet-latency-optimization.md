# 2026-09-30 公网延迟优化与现网复测

本文只记录本窗口在已有互联网接入基础上完成的延迟排查、代码修改、部署和复测。Cloudflare 隧道、域名、PHP 认证、游戏规则与原有客户端界面不是本次新增成果。当天较早的接入与长测记录见 [互联网接入工作日志](2026-09-30-internet-access-worklog.md)；其中“源站压缩未部署”描述的是当时的状态，本次后续工作已将压缩和其他延迟修复部署到本机现网。

## 本次完成的修改

| 本地提交 | 实际修改 | 目的 |
| --- | --- | --- |
| `de1312c` | 游戏 Host 对 `/connect` 按客户端 `Accept-Encoding` 启用 gzip 响应压缩 | 缩小首次完整世界快照的传输量 |
| `d773a84` | 客户端待发送玩家命令时取消正在进行的只读 `/poll`，优先发送命令 | 避免命令排在一次慢轮询之后 |
| `61e3614` | 后台计时任务的六个只读收集器共用一次载入的独立世界状态；取消覆盖整轮后台处理的世界锁，改为每条提交命令单独加锁；轮询可读取 SQLite 已提交快照；命令执行省去一次约 12 MB 世界状态的深拷贝，并在拒绝时重新载入原状态；会话不回退到较旧修订版 | 减少后台计算对轮询和玩家命令的阻塞 |

源码里的耗时日志仅在设置 `DWSG_LATENCY_TRACE=1` 时输出。本次使用的测试脚本、账号、数据库副本、备份、日志和构建产物在被忽略的 `audit/` 中，没有加入 Git 提交。

## 验证与实测

Host 的 Release 构建通过，零警告、零错误；战斗运行检查通过 115 项。并发检查验证了后台命令仍在计算时，轮询能够读到已提交快照。客户端网络脚本在隔离的 Unity 6 批处理工程中编译通过；本次没有用项目标注的 Unity 2022 版本重新构建正式玩家包。

以下轮询数据每组各取 20 次。修复前后隔离服务使用世界数据库副本，但后台任务随时间变化，所以这些数字是实际运行对照，不能当作严格同负载基准。

| 路径与版本 | 轮询中位数 | 轮询 P95 | 首次连接 |
| --- | ---: | ---: | ---: |
| 修复前，本机隔离服务 | 5,984 ms | 9,101 ms | 11,935 ms |
| 修复后，本机隔离服务 | 962 ms | 1,571 ms | 2,909 ms |
| 修复后，本机现网入口 | 850 ms | 1,185 ms | 1,507 ms |
| 修复后，从服务所在电脑经 `game.dwsg-game.com` | 1,261 ms | 1,587 ms | 4,047 ms |

隔离服务的 `/connect` 响应不压缩约 651 KB，请求 gzip 后约 74 KB；公网复测的压缩连接响应约 74 KB。单次本机压缩请求并没有比不压缩请求更快，因此不能把首次连接耗时的改善单独归因于 gzip。

修复版先在端口 57120 和数据库副本上验收，再备份本机现网 SQLite 数据库并切换端口 57119 的游戏 Host；切换脚本在启动或健康检查失败时可启动原二进制文件回滚。切换后，本机与公网 `/health` 均返回 200；测试账号经公网域名完成登录、连接、20 次轮询和断开；SQLite `PRAGMA quick_check` 返回 `ok`。日后本机启动脚本使用的默认 Host 构建目录也已放入与此次验收二进制一致的文件，并核对了关键文件的 SHA-256。

## 仍待处理

- 公网复测是在服务所在电脑上绕经 Cloudflare 域名完成的，没有代表异地宽带、手机移动网络或 RK3568 的实际延迟。
- 本次没有完成玩家实际业务命令的端到端耗时分布、五人同时在线负载和长时间稳定性复测；不能据此宣称这些场景已稳定。
- 现网轮询仍约 0.85 秒本机中位数、1.26 秒公网路径中位数，首次公网连接约 4.05 秒。世界数据约 12 MB，每次快照仍需从 SQLite 载入和解析；后续优化应先测量这一段和玩家命令耗时，再决定是否引入缓存或调整后台任务频率。
- GitHub 只保存源码和本文档，不包含被忽略的运行时数据库、真实配置、账号或本机部署二进制文件；其他机器需要按其环境重新构建和部署。
